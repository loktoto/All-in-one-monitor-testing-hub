# 產品方向：路線圖、依賴與介面規格

內容調查日期：2026-11-13；文件及連結狀態覆核：2026-11-15。下列內容是根據[產品證據](01-product-evidence.zh-Hant.md)提出的設計建議，不是現有功能或發布承諾；能力編號見[去重目錄](02-capability-catalog.zh-Hant.md)。先完成可辨識的讀值、取消與保護，再擴大負載；先固定可重現的測試配置與版本，再提供跨次比較。這些依賴不能只靠畫面上的警告取代。

## 決策原則

- **觀測、驗證、壓力、基準分開說清楚。** 即時負載不是硬體診斷；算錯代表該次工作偵測到不一致，不一定能單獨確定故障零件；完成、停止、失敗、未完成及不可用分開。
- **以真實來源為準。** 不提供虛構溫度／SMART／分數；零、未提供、讀取失敗、過期分別表示。每一項保留來源、裝置、單位與時間，不能將不同廠商或 API 的欄位憑名稱合併。
- **本機優先、手動操作、預設小負載。** 不以後台帳戶、雲端、上傳或寫入硬體設定作基本要求。檔案測試有時間、容量、總寫入／空間上限，不能打開 raw disk 或既有檔案寫入。
- **不把風險較高的功能藏在「開始」裡。** 不預設啟用組合高負載、磁碟大量寫入、風扇／時脈修改、長期記錄、追蹤或自動化。保留取消、停止原因和測試是否完整。
- **漸進增強。** 新手看結論、核心指標和建議；進階使用者可查看來源、工作負載、記錄和限制。不能因顯示簡單而隱藏未知或故障。

## 測量與安全資料契約

### 感測器與時間

建議每個樣本攜帶 `device_id`、`metric_id`、`value`（可缺）、`unit`、`source/provider`、來源量測時間、收取時間、支援／錯誤／過期狀態及校驗用版本。使用單調時鐘判定停留／逾時，牆鐘只供人閱讀。統計區間要記錄起點、取樣率與丟樣數；不把缺樣補成零。指標映射未確認時保留各來源分開列示，避免兩個 GPU 同名或一個 GPU 有多個 API 被算成多張實卡。SMART 標籤應顯示協定、原始值與來源解釋，不能將廠商差異強制套入同一健康公式。

### 測試結果狀態

- **Completed**：按計畫完成或達到使用者設定的正常測試時長，且已完成最低驗證單位；記錄實際完成量和結束原因，不代表整機無故障。
- **Stopped**：使用者或保護策略要求提前停止，並保存已驗證量及停止原因。正常達到預定時長並不算提前停止；操作異常逾時應依錯誤類型記為 Failed 或 Inconclusive，另存逾時原因。無法確認停止時顯示「停止中／無回應」，不可假裝已停止。
- **Failed**：可記錄驗證不一致、I/O／驅動／程序錯誤等具體原因，**不自動等同硬體損壞**。
- **Inconclusive**：時間結束或觀測不足，未完成足夠驗證；保留資料缺口。
- **Unavailable**：裝置、權限、驅動、測試能力或可信安全資料不可用；不顯示偽造零值或假通過。

結果需另存：工作負載版本／參數／實際開始結束、worker／實測記憶體／文件與寫入量、設備及提供者版本、測量來源與缺值、錯誤分類、取消／門檻事件，以及隱私遮蔽選項。文字摘要給人看、結構化格式給工具讀；匯出預覽及明確保存目的地，不預設覆寫。

### 基準設計與比較

工作負載 profile 應標記測試類型與演算法／格式版本、平台、設備、資料型態、block size、queue depth／worker、預熱／測量／冷卻時間、完成次數與快取政策。原始量測含單位：吞吐量、每秒操作數、延遲樣本或分佈；幀時間與 FPS 各自定義。統計需列出有效樣本數和離群／缺失處理。先在完全相同的負載及版本下比較，同時展示驅動、裝置、電源／溫度與背景工作差異；跨版本結果標「不可直接比較」。不要把硬體驗證回合數、供應商廣告分數或其他工具的專有分數冒充成同一量尺。

### 平台、權限與授權

預設程式為無管理員權限的唯讀來源；**預設不捆綁或安裝未簽署的 kernel driver**。若日後需要額外感測，評估來源文件、硬體範圍、風險、Windows 簽章／發布要求及維護能力，才提供清楚標示且自願的受審核簽署 provider；provider 應隔離失敗、能卸載／停用並顯示權限與來源。並非所有感測都必須使用驅動，簽章也不保證正確或安全。

HWiNFO 的商業使用、共享記憶體及嵌入需按其[授權](https://www.hwinfo.com/licenses/)與[條款](https://www.hwinfo.com/files/license.pdf)審查；不假設能繞過限制。LibreHardwareMonitor 是 MPL-2.0 且含第三方條款；若整合需評估檔案級義務、動態／子程序方式與來源公告，並非法律結論。PresentMon、DiskSpd 等亦須檢視各上游的現行授權及第三方項目；NVML 需可用的 NVIDIA 驅動及 SDK／分發條件。ETW／某些 SMART 或感測來源可能需要管理員、群組權限、特定驅動或裝置通道，應將授權失敗當作可觀測狀態。風扇／時脈寫入不可透過這些唯讀 provider 偷渡。

## 建議的介面流程

### 1. 首頁「總覽」

上方為 CPU、記憶體、GPU、實體磁碟概況和「最後更新」；每卡有目前值、單位與來源可展開資訊。圖表帶圖例、時間、缺值間斷；點擊卡片進入該裝置。顯示可用、過期與不可用數量，不把缺少資料變成健康分數。初學者預設只看主要讀值；進階頁顯示完整裝置樹、統計／取樣頻率和 provider 錯誤。

### 2. 「測試」：三個清楚的用途

- **驗證正確性**：CPU 已知答案、程序記憶體、GPU 計算、檔案回讀；顯示預計時間、覆蓋及無法涵蓋部分。
- **壓力測試**：以 CPU、GPU、記憶體或未來的組合模式施加負載；開始前顯示來源、目前溫度是否新鮮、停止條件、資源與限額。沒有可靠溫度資料時明白顯示「沒有自動熱保護」。
- **效能基準**：只在版本化工作負載就緒後出現；先選項目／設定檔，展示預熱、測量、磁碟寫入量與版本，完成後才提供同設定比較。

開始前有獨立的負載摘要；文件測試呈現選定目錄、預估占用與最多寫入量。執行時顯示已用／剩餘時間、實際驗證量、溫度來源狀態、錯誤及醒目的停止按鈕；不把預估完成百分比當作已驗證量。結束後顯示狀態及具體限制，並可查看報告。

### 3. 「報告與記錄」

顯示時間線、測項、狀態、實際覆蓋和操作；詳情展開設定、設備、來源、錯誤及停止原因。匯出前預覽資料並選擇是否遮蔽序號／路徑／機器名稱；明示結果只存於本機的保留期。比較畫面逐項核對工作負載和版本，不合條件就解釋原因。自動分享、外發及帳戶登入並非預設流程。

### 4. 「進階」

顯示 provider、資料新鮮度、權限及相容性；將 ETW、外部程式、風扇控制及商業整合放在獨立可選區。對每項增加可能消耗的資源、權限和停止行為說明。遇到不支援硬體、虛擬機、RAID 或缺少驅動時，提供可執行的下一步而非通用紅色錯誤。
