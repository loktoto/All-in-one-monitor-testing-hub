# Architecture and follow-up

The egui event loop only renders snapshots and queues manual tests. A separate module (`specs`) collects the specification sheet once at startup on its own thread: on macOS it runs read-only `sysctl`, `system_profiler`, `diskutil` and `pmset` queries and parses their documented text output; on Windows/Linux it falls back to `sysinfo` and reports the remaining fields as unavailable. Graphics discovery asks for exactly one platform backend (Metal, DX12 or Vulkan) so a device is not listed once per API, and NVML is loaded only where the NVIDIA driver library exists. A telemetry thread refreshes `sysinfo`, discovers wgpu adapters and queries optional NVML. A separate worker runs one test with an atomic cancellation flag and records a result. Memory allocations, CPU worker count, test duration, temporary file size and cumulative file writes are bounded. GPU work uses small buffers and reads back each completed dispatch. No kernel driver or elevated privilege is installed. The UI and test workers do not send telemetry over the network.

Known gaps: CPU uses one fixed known-answer integer vector; systematic faults outside that workload may go undetected. Memory patterns cover only the allocated process memory and may be optimized/cached by the OS or hardware. File verification can be served by caches even after `sync_all`, and is not a raw-media test. GPU dispatch is a basic compute check, not a graphics/VRAM/thermal qualification; driver hangs can delay cancellation. NVML is dynamically discovered and absent on non-NVIDIA systems. Telemetry is best effort. One backend is chosen at discovery to avoid backend duplicates; same-name NVML matching is a labelled heuristic and ambiguous devices stay separate. Collection age is not a sensor-provided timestamp.

Future work: real Windows hardware validation, physical device-to-volume mapping, SMART, device-to-temperature mapping, AMD/Intel sensor providers, richer test progress and persistent reports. Any thermal automation must explicitly handle missing/stale sensor values. A GPU worker should eventually be isolated in a process to recover from stuck drivers.
