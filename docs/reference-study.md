# Reference study and feature gaps

This is a public-documentation study performed 2026-11-13. We followed the *study → build → check* structure described in [Craft Anything's README](https://github.com/storytold/craft-anything#how-it-works): collect evidence, implement independently, then compare capabilities and record gaps. We also reviewed [REA's evidence-and-limitations workflow](https://github.com/morluto/rea). This was a manual application of those workflows; neither tool was executed, and no proprietary program or binary was inspected. Product documentation describes vendor capabilities; it does not establish behavior on the user's hardware.

| Evidence from official project documentation | This MVP | Gap / follow-up |
| --- | --- | --- |
| [HWMonitor](https://www.cpuid.com/softwares/hwmonitor.html) lists voltages, temperatures, power, current, fan speeds, load and clocks. | CPU load and supported NVIDIA GPU temperature/load are shown; missing sensors are explicit. | Add sensor providers for CPU, other GPUs, motherboard and storage only after testing privilege, device coverage and missing-value handling on Windows. |
| [CPU-Z](https://www.cpuid.com/softwares/cpu-z.html) lists CPU identification/cache, memory type and SPD, and real-time core and memory frequencies. | CPU model, logical CPU load and OS memory capacity/usage. | Processor package, cache, frequency, memory timing/type and SPD remain unimplemented. Do not infer them from capacity. |
| [FurMark](https://geeks3d.com/furmark/) describes a very intensive GPU stress test and OpenGL/Vulkan graphics benchmarks. | Small compute dispatch and result readback, with stop and bounded resources. | This is a light compute correctness check, not a graphics benchmark or comparable GPU load. A future GPU stress mode needs separately validated workload control, GPU selection, driver isolation, temperature handling, and clear metrics. |
| [LibreHardwareMonitor](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor) documents sensors including temperature, fans, voltages, load and clocks, across CPUs, GPUs and storage; it notes that some sensors require administrator rights. | Direct sysinfo, wgpu and optional NVML providers; no bundled driver or elevated privilege. | Evaluate a separately packaged, opt-in provider on actual Windows machines, including privilege, compatibility and licensing review. LibreHardwareMonitor is MPL-2.0 with additional third-party notices; it is not incorporated here. |

Checks against this MVP: the overview exposes current CPU/memory activity and per-core load, labels missing sensors, and distinguishes volume information from physical hardware. The tests expose manual start, stop, bounds and verified-work reporting. Results are not equivalent to the reference products. The Linux GUI was smoke-tested with a software Xorg display; reference applications and actual Windows hardware have not been exercised here.
